# Security assessment evidence register

Status: local implementation evidence only; independent penetration test, deployment assessment and certification pending. This register is not a SOC 2 report, ISO certificate, ASVS verification statement or legal opinion.

Control evidence lives in governance/operations/platform/tenant tests, existing private-group revocation tests, tool-security/execution/delegation/recovery suites, connector OAuth/idempotency/reconciliation tests, and Chromium customer workflows. New governance browser coverage checks labels/contrast and critical admin interactions. Automated axe checks cover a defined browser surface; screen-reader, keyboard-only, native-client and cross-language acceptance remain pending.

The restore drill produces synthetic evidence for encrypted/signed logical backups, corruption rejection and restored records. It does not qualify managed PITR, object/media restore, deleted-data suppression, regional failover or external provider state. The load fixture is a baseline, not a production capacity result.

Use the [OWASP ASVS requirements](https://asvs.owasp.org/) as a structured assessment input. Before launch, record the version, selected level, scoped components and every unmet/not-applicable requirement with evidence and review owner. An independent tester should cover tenant and cross-organization authorization, invitation/token lifecycle, SSO/SCIM/MFA, export/draft/cache revocation, upload/DLP/download/range/sharing, SSRF/DNS rebinding, webhook replay/signatures, OAuth mix-up, remote MCP/tool approval/capabilities, sandbox escape, prompt injection and source exfiltration, budget races, billing replay, media consent and support grants.

Each assessment record must include: exact source revision and immutable image digests; environment and providers; test identity/role/audience matrix; method, timestamp and reviewer; observed findings with severity and reproduction; evidence artifact hashes; remediation and retest; remaining exceptions with expiry. Avoid storing credentials or customer bodies in artifacts. The release preflight accepts signed, build-bound artifact envelopes, not an unchecked checkbox.

Outstanding operational evidence includes independent append-only audit anchors, deletion receipts mapped to real component inventories, key retirement drills, incident paging exercises, real storage scanning, runtime recovery/fencing, signed client updates and store distribution, payment/provider sandbox tests, native and assistive-technology accessibility, customer pilot workflows, realistic hot-tenant/soak load and verified completion/cost analytics.
